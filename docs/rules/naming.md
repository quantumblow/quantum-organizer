# 命名与归档规则（唯一真源）

这份文档是 `quantum-organizer`（Python）与二期手机 App（Dart）共同实现的规范。
两边必须跑同一份黄金用例：`tests/fixtures/naming_cases.json`。

## 1. 目标文件名

```
<stem>_<省>_<第二级>_<YYMMDD><ext>
```

- `<stem>`：去掉旧后缀后的原文件名（相机前缀里的下划线保留）。
- `<省>`：省级名称清洗后（见 §3）。
- `<第二级>`：市级名称；直辖市与港澳是**所在区**（见 §4）。
- `<YYMMDD>`：拍摄日期，6 位数字。
- `<ext>`：原扩展名，原样保留大小写。

示例：

| 原文件 | 目标 |
|---|---|
| `IMG_1234.jpg`（南京拍摄，2014-08-15） | `IMG_1234_江苏_南京_140815.jpg` |
| `DJI_0189.mp4`（南京拍摄，2021-09-21） | `DJI_0189_江苏_南京_210921.mp4` |
| `DSC_0001.JPG`（北京东城区，2024-01-01） | `DSC_0001_北京_东城区_240101.JPG` |

## 1.1 段选择（改名可选）

后缀由三段组成，可以只取其中几段；选择顺序固定为 `省 → 市 → 时间`，与勾选顺序无关：

| 选择 | 结果 |
|---|---|
| 省 + 市 + 时间（默认） | `IMG_1234_江苏_南京_140815.jpg` |
| 省 + 市 | `IMG_1234_江苏_南京.jpg` |
| 市 | `IMG_1234_南京.jpg` |
| 时间 | `IMG_1234_140815.jpg` |
| 不改名 | `IMG_1234.jpg`（只按省/市归档，名字原样保留） |

不变的部分：**归档目录始终是 `<省>/<第二级>/`**，与是否改名无关；没有 GPS 的文件仍不参与。

拍摄时间为空时不硬塞时间段（选了「省+市+时间」而文件没有拍摄日期，结果退回「省+市」）。

## 2. 幂等

若 stem 已匹配 `(.+)_(省)_(市)_(6位日期)`（末尾的冲突后缀 `_2`、`_3` … 先剥掉），
先剥旧后缀再追加新后缀，**绝不叠加**：

- `IMG_1234_江苏_南京_240815.jpg` 再跑一次 → 仍是 `IMG_1234_江苏_南京_240815.jpg`。
- `DSC_0001_北京_东城区_240101.JPG` 换了城市 → `DSC_0001_上海_黄浦区_240102.JPG`。

省份/城市字段不允许是纯数字（避免把 `DSC_0047_140620_140620` 这类旧文件名误判成地名）。

段选择的幂等：先精确匹配「即将生成的后缀」再剥离，因此任何组合重复跑都不叠加；
从「省+市+时间」切到「省+市」时会把旧的时间段一并去掉（`IMG_1234_江苏_南京_240815` →
`IMG_1234_江苏_南京`）。纯数字尾巴（`DSC_0047_140620`）不会被当成日期段剥掉。

## 3. 省份清洗

去掉 `省`、`市` 后缀；五个自治区与两个特别行政区用固定短名：

| 原始 | 输出 |
|---|---|
| 江苏省 | 江苏 |
| 内蒙古自治区 | 内蒙古 |
| 广西壮族自治区 | 广西 |
| 西藏自治区 | 西藏 |
| 宁夏回族自治区 | 宁夏 |
| 新疆维吾尔自治区 | 新疆 |
| 香港特别行政区 | 香港 |
| 澳门特别行政区 | 澳门 |

## 4. 第二级清洗

1. 去掉行政级别后缀：`自治州|自治县|自治旗|特别行政区|自治区|地区|省|市|盟|县|林区`。
2. 反复剥掉结尾的 `<民族>族`（民族 stem 表见 `src/quantum_organizer/naming.py`）。
3. 若原名以 `自治州` 结尾，再剥一次结尾的裸民族简称（`蒙古`、`柯尔克孜`、`维吾尔`、`哈萨克`、`达斡尔`）。
4. **保留 `区`**：`东城区`、`黄大仙区`、`浦东新区` 原样保留。

| 原始 | 输出 |
|---|---|
| 南京市 | 南京 |
| 东城区 | 东城区 |
| 湘西土家族苗族自治州 | 湘西 |
| 海西蒙古族藏族自治州 | 海西 |
| 博尔塔拉蒙古自治州 | 博尔塔拉 |
| 克孜勒苏柯尔克孜自治州 | 克孜勒苏 |
| 酉阳土家族苗族自治县 | 酉阳 |
| 大兴安岭地区 | 大兴安岭 |
| 阿拉善盟 | 阿拉善 |

**直辖市与港澳的第二级是所在区**：`北京/东城区`、`上海/黄浦区`、`香港/中西区`、`澳门/花王堂区`。
下游工具一律按位置取层级（省=第一段，第二级=最后一段），不要假设第二级一定是"市"。

## 5. 目录结构

- 默认原地：`<源目录>/<省>/<第二级>/<目标文件名>`。
- `--output DIR`：统一输出到另一个根目录，源目录不动。
- 无省市可解析的文件（无 GPS、境外、台湾数据缺失）：**默认不动**，只在报告里给出 `reason`。
- `--move-unlocated`：把它们收进 `<源目录>/未定位/`，**不改名**。

## 6. 冲突

目标已存在时，在 stem 尾部追加 `_2`、`_3`……（扩展名不变）。执行前若发现目标仍被占用，
该条记为 `conflict` 并跳过，**绝不覆盖已有文件**。

`--copy` / `--output` / `--move-unlocated` / `--allow-estimate` 属于**扫描选项**：
它们决定计划的内容与执行语义，随计划一起持久化；`apply` 只认计划里存的选项，
缺选项时直接拒绝（fail closed），不允许退回默认的 move 语义。

## 7. 日期来源优先级

1. EXIF `DateTimeOriginal`（本地时间）
2. 视频 `creation_time`
3. 文件名里已有的 6 位 `YYMMDD`
4. 文件修改时间（报告中标 `time_source=mtime`）

v0.1 不做时区推断：视频的 `creation_time` 常是 UTC，跨午夜时日期可能差一天，报告里用 `time_source` 标注来源。

## 8. 名称安全

- 非法字符 `< > : " / \ | ? *` 与控制字符替换为 `-`。
- 去掉尾部空格与点。
- UTF-8 字节数 ≤ 200，超长时**只截 stem**：省市与日期是归档依据，必须留着（冲突后缀 `_2` 也计入预算）。
